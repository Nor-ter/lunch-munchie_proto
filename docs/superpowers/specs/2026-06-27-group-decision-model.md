# 그룹 결정 모델 — 하이브리드 (least-misery로 좁히고 → 투표)

- 날짜: 2026-06-27
- 상태: **로직 확정 (A·B~F 전부) · 문서 = 이 파일 · 코드는 미반영(C·B·D·E 수정 예정)**
- 배경: 그룹 결정의 정합성 논의 — "여러 명이 결승 다시를 하면 하나로 수렴 안 되는 문제"에서 출발.
- 관련: [결정 메커니즘 PDF](../../engine/lunchie_decision_mechanics.pdf) (솔로 '둘 다 별로' & 재진입), `server/engine/group.ts`.

## 0. 왜 이 문서

목적함수(무엇을 최적화하나)를 안 정한 채 단계마다 다른 기준(슬레이트=least-misery,
예선 랭크=싫어요, 결승=다수결)이 섞여 있었다. 먼저 목적을 정하고, 거기서 B~F를 도출한다.
**코드보다 이 모델이 먼저다.** 현재 코드는 이 모델의 일부만 구현한 잠정 baseline.

## A. 목적함수 — 확정: **하이브리드**

> least-misery로 "아무도 크게 싫어하지 않는" 안전한 top-2로 좁힌 뒤, 그 둘 중엔 **다수결**.

- 최소 후회(거부권)와 최대 만족(다수결)의 절충.
- least-misery는 **안전 필터**(누가 미워하는 곳 제거), 투표는 **인간의 최종 선택**.
- 솔로는 개인 듀얼(2AFC), 그룹은 이 합의 모델. 둘은 분리.

## 확정 모델 (하이브리드 v1)

```
예선(PRELIM)  각자 LIKE/DISLIKE
   └ 완료 = 전원 OR 호스트 '지금 진행' OR 마감
        ↓
후보 선정     least-misery 랭크에서 top-2 (좋아요≥1 · 과반에게 미움받지 않은 곳)
   ├ 후보 0  → 바로 reroll (아무도 안 좋아함 = 강제 우승 금지)
   ├ 후보 1  → 만장일치(전원 LIKE·싫어요 0)? 예→바로 확정 / 아니오→"이걸로 / 별로" 확인 투표('별로' 다수→reroll)
   └ 후보 2+ → 결승(FINAL)
        ↓
결승(FINAL)   3지선다: A / B / 둘 다 별로   (1인 1표)
   └ 완료 = 전원 투표 OR 호스트 OR 마감
        ↓
확정(DONE)
   ├ '둘 다 별로' 단독 최다 → reroll: 거절·다수미움 제외 + 새 후보 섞어 재스와이프 → 새 결승
   │                          (reroll 상한 N회 초과 → "합의 실패" 안내. 1위 폴백 없음)
   └ 그 외 → 표 많은 곳. 동률 → 예선 상위(least-misery top)
```

## B~F 결정

### B. 결승 트리거 · 후보 수 분기
- "후보" 자격 = 좋아요 ≥ 1 **그리고** 과반에게 미움받지 않음(들러리 배제: 소수만 찍은 곳은 결승 진출 X).
- **후보 0** → 바로 reroll (아무도 안 좋아함 = 강제 우승 금지).
- **후보 1** → 만장일치(참여자 전원 LIKE·싫어요 0)면 바로 확정; 아니면 **"이걸로 / 별로(다른 곳)" 확인 투표** — '별로' 다수면 reroll. (escape가 1곳 케이스에도 있게 — veto 일관성.)
- **후보 2+** → 결승 3지선다. → 모든 케이스(0·1·2)에 escape 일관.

### C. 그룹 탈출구 ★ (원래 문제의 답 · **확정**)
- 결승을 **A / B / "둘 다 별로"** 3지선다로. per-person이 아니라 **그룹 다수결**이라 수렴 유지.
- "둘 다 별로"가 **단독 최다** → **reroll**. reroll 후보 풀:
  - **제외 (누적)**: ① 거절된 결승 후보(A·B) + ② **다수가 싫어한 곳**(`dislikeCount > 멤버수/2`). 라운드마다 제외 집합이 쌓여 풀이 깨끗해짐.
  - **유입**: 새 추천(반경·필터 완화 / 탐색 가중↑)으로 안 보던 신선한 곳 — **거절·미움 재탕 금지, 새 선택지 섞기**.
  - **유지**: 남은 후보 중 소수만 싫어한 곳.
  - → 신선해진 풀로 **재스와이프(PRELIM′) → 새 결승(FINAL′)**.
- **무한 방지**: reroll 상한 N회(기본 2~3) 초과 → **"합의 실패" 안내**("오늘은 합의가 안 됐어요 · 다른 동네/나중에"). *1위 폴백은 폐기 — 이미 거절한 곳을 도로 주는 모순이라.*
- 솔로의 "0개 → 새 추천·재스와이프"를 그룹은 "'둘 다 별로' 최다 → 미움 빼고 새 후보 섞어 재스와이프"로 — 한 방향.

### D. 정족수 · 노쇼
- 예선/결승 완료 = `전원 OR 호스트 '지금 진행' OR 마감`. 노쇼가 타이머까지 전체를 잡지 않게 호스트 강제 진행.
- 마감 시 던진 표로 결정. 0표면 least-misery 1위.
- (호스트 버튼은 UI 후속 — 로직은 "강제 진행 트리거"만 필요.)

### E. 동률 · 마감
- 결승 표 동률 → 예선 상위(least-misery top).
- "둘 다 별로"는 **단독 최다일 때만** reroll(동률이면 결정 쪽 = 무한 reroll 방지).
- 예선 동률 → 좋아요 수 → 엔진 순위로 **결정적** 정렬.

### F. 일관성
슬레이트 · 예선 랭크 · 후보 선정 모두 least-misery(안전 필터), 결승만 투표, "둘 다 별로"가 안전밸브.
한 방향으로 일관.

### G. 수집 데이터 (학습 신호) ★
**모든 행동이 학습 신호다 — 거부·reroll·합의실패도.** 결정에만 쓰고 버리지 않고 엔진에 먹인다.

| 그룹 단계 / 행동 | 이벤트 | 엔진 신호 |
|---|---|---|
| 예선 노출 | IMPRESSION (PRELIM, propensity) | off-policy(IPS) 기반 |
| 예선 스와이프 | SWIPE LIKE/NOPE (round1) | 멤버 취향 θ(pointwise) + least-misery 집계 |
| 결승 노출 | IMPRESSION (FINAL ×2, propensity) | 슬레이트 품질(off-policy) |
| 결승 A 선택 | SWIPE CHOOSE (FINAL, opponent_id) | 멤버별 pairwise A>B |
| **둘 다 별로** | SWIPE NOPE ×2 (FINAL) | A·B 음성(역치 미달) + 슬레이트 미스 |
| **별로(단일 확인)** | SWIPE NOPE (FINAL) | 그 후보 음성 |
| **reroll** | REROLL + 제외된 '다수 미움' 곳 = 강한 음성 | 불만족·피로 + 그 컨텍스트 음성 |
| **합의 실패** | 🆕 `NO_CONSENSUS` (신규 이벤트 타입) | 슬레이트 품질↓ · 탐색 필요 |
| 우승 | WINNER | 취향(+)·satiation·chain |

- 특히 "둘 다 별로"·"다수 미움(reroll 제외)"은 *명시적 음성*이라 값지다 — 현재 버려지고 있음.
- 신규 이벤트 `NO_CONSENSUS`를 `shared/engine.ts` EVENT_TYPES에 추가.
- 코드 구현 시 **결정 로직 + 이벤트 로깅을 같이** 넣는다(로깅 누락 방지).

### 구현 노트 (코드 구조)
- **세대(gen) = round 인코딩**: 예선 = `2G−1`, 결승 = `2G` (G=1,2,…). 기존 swipes 재사용, 스키마 변경 없음. 현재 세대 = 최대 round 기준.
- **"둘 다 별로" 표 = sentinel** `restaurant_id = "__reject__"` (결승 round-2 LIKE). 후보1 확인 투표도 "후보 vs `__reject__`"로 통일 — 3-way가 confirm 케이스까지 흡수.
- **`decideGroup`**: 현재 세대 상태기계 + 3-way 집계 → `DONE` / `REROLL`(+제외집합) / `NO_CONSENSUS`(세대 > cap).
- **제외집합** = 누적(거절 finalists + `dislike > 멤버/2`). `REROLL`이면 route가 제외를 빼고 fresh 슬레이트(필터 완화)로 다음 세대 예선 구성.

1. **C** — 결승에 "둘 다 별로" 3지선다 추가 + reroll(거절·다수미움 제외 + 새 후보 섞어 재스와이프) + reroll 상한 초과 시 "합의 실패" 안내.
2. **B** — 후보 자격에 들러리 필터(`dislikeCount > 멤버수/2` 배제) + 후보0(바로 reroll)·후보1(만장일치 아니면 "이걸로/별로" 확인 투표) 분기.
3. **D** — 호스트 '지금 진행' 트리거(완료 조건에 추가).
4. **E** — 예선 결정적 tiebreak(좋아요 수 → 엔진 순위).
5. **G** — 음성 신호 로깅(둘 다 별로·별로·reroll 제외 곳·`NO_CONSENSUS`) + EVENT_TYPES에 `NO_CONSENSUS` 추가.
