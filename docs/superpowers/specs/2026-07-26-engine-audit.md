## 2. 어디에 쓰이나 (학습 → 서빙)

```
SWIPE LIKE/NOPE  → updateTaste(x, y=1/0, w=1)      ┐
CHOOSE           → updatePairwise(x_win, x_lose,    ├→ θ 사후분포 N(μ, A⁻¹)
                    w=pairwiseWeight(decision_ms))  │   (베이지안 선형회귀)
WINNER           → updateTaste(w=2) + recordConsumption + recordStop
COURSE_SAVE      → updateTaste(w=3)                ┘
IMPRESSION       → recordExposure → exposurePenalty
WINNER 시퀀스     → chain 전이 P(next|prev)  (6h occasion)

서빙: score = 0.4·평판 + 0.3·맥락 + 0.3·취향(θ 샘플)
              − 0.3·노출피로 + 0.3·재소비 + 0.4·연쇄
      → softmax(τ=0.15) + ε 혼합 → 비복원 샘플링 K개
```

# 3. 검증 결과 (실측)

## 🔴 치명 1 — 평판 항이 죽어 있다 (점수의 40~60%)

**측정**: 카탈로그 118곳 **전부 `rating=0, review_count=0`**.
→ `reputation = 0.7·norm(0) + 0.3·norm(0) = 0` (모든 후보 동일).

콜드 유저 점수는 `0.6·0 + 0.4·contextFit`, 학습 유저는 `0.4·0 + 0.3·cf + 0.3·taste`.
**설계가 의도한 평판 신호가 통째로 사라졌다.**

**원인**: 드라이브 전용 카탈로그로 전환하면서 신규 식당에 평점을 채우지 못했다(내가 만든 회귀).

## 🔴 치명 2 — 점수 분산 붕괴: 118곳 → **고유 점수 2개**

**측정** (콜드 유저, companions=1):
```
점수 범위 0.200 ~ 0.260 (폭 0.060) · 고유값 2 / 118곳
```
**메커니즘**: 평판=0이라 `contextFit`만 남는데, 이건 카테고리 정규식 몇 개다.
`companions=1`이면 `/카페|베이커리|일식|.../` 매칭 여부로 `cf ∈ {0.5, 0.65}` 두 값뿐
→ `base = 0.4·cf ∈ {0.200, 0.260}`. 정확히 관측값과 일치.

**의미**: **콜드 유저에게 엔진은 순위를 매기지 못한다.** 사실상 동점 무작위다.
"추천"이라 부르지만 실제로는 카테고리 2분류 + 랜덤이다.

## 🔴 치명 3 — propensity가 틀렸다 → **off-policy 평가 전체가 편향**

**측정** (4,000회 슬레이트, K=7):
```
실제 노출률 / 로깅된 propensity =  평균 7.07x · 최소 5.86x · 최대 14.54x
```
**두 가지 문제**:
1. **일괄 과소** — 로깅값이 실제의 1/7. `probs[i]`는 **첫 draw에서 뽑힐 확률**인데,
   실제로는 K=7번 draw 중 **한 번이라도** 뽑히면 노출된다. 마진 포함확률이 아니다.
2. **편향이 균일하지 않다** (5.9x~14.5x, 2.5배 차이) — 상수배면 IPS 비율이 상쇄되지만,
   항목마다 배율이 다르면 **상쇄되지 않는다.** 고노출 항목일수록 더 과소평가(14.5x)돼
   IPS가 **드물게 노출된 항목의 가치를 과대추정**한다.

**의미**: `getMetrics`의 off-policy 지표·A/B 판정이 **체계적으로 왜곡**된다.
엔진 개선 여부를 측정하는 계기 자체가 고장 나 있다.

## 🟡 개선 1 — pointwise와 pairwise를 같은 A·b에 누적

`updateTaste`(x, y∈{0,1})와 `updatePairwise`(d = x_win−x_lose, y=1)가 **같은 사후분포**에 쌓인다.
x는 [0,1] 양수만, d는 [−1,1] 부호 있음 — 예측 대상이 다르다(선호 확률 vs 선호 마진).

**반론(자기검증)**: 이론적 불순함이 실제로 해를 끼치는가? → **실측함**:
```
A. pointwise만  : 기름진 0.734 vs 가벼운 0.504
B. pairwise만   : 0.644 vs 0.397
C. 혼합(실제 앱): 0.743 vs 0.500   ← 분리 유지, θ norm 0.829
```
**결론: 실害 없음.** 두 신호가 같은 방향을 가리켜 혼합이 오히려 강화한다.
→ **치명이 아니라 정밀도 개선 항목**으로 강등. (분리 학습은 데이터 쌓인 뒤 검토)

## 🟡 개선 2 — 절편(bias) 항 없음
피처 8차원에 상수 1 성분이 없다 → 모델이 **기저 선호율**을 학습할 수 없고,
모든 설명을 8개 맛/가격 축에 억지로 싣는다.

## 🟡 개선 3 — contextFit의 사각지대
`레스토랑`(11곳)·`바`(10곳) 등 21곳은 어떤 정규식에도 안 걸려 `cf=0.5` 고정.
날씨·시간 규칙도 한글 카테고리 전제 — 카탈로그가 영문으로 바뀌면 `features.ts`와
**같은 종류의 버그**가 재발한다(그 버그는 이번에 고쳤으나 `scorer.ts`는 그대로).

# 4. 최적화 제안 (우선순위)

| # | 조치 | 효과 | 비용 |
|---|---|---|---|
| **P0** | **propensity를 마진 포함확률로 수정** | off-policy·A/B 계기 복구 | 함수 1개 |
| **P0** | **평점 확보** (Places 또는 사진 기반 대체 지표) | 죽은 40% 신호 부활 | 데이터 |
| **P1** | **contextFit를 피처 기반으로 교체** | 점수 고유값 2 → 연속값 | 중간 |
| **P1** | 절편 항 추가 (FEATURE_DIM 8→9) | 기저율 학습 | 소 |
| **P2** | 콜드스타트에 피처 다양성 주입(MMR 등) | 초기 탐색 품질 | 중간 |
| **P2** | pointwise/pairwise 분리 학습 | 정밀도 | 중간 |

### P0-a. propensity 수정 (가장 급함)
현재: `propensity = probs[i]` (첫 draw 확률).
수정: **K회 비복원 추출에서의 마진 포함확률**. 정확한 계산은 조합 폭발이라,
실용적으로 **몬테카를로 추정**(같은 분포에서 M회 샘플링해 포함 빈도) 또는
**Sampford/순차 근사** `1 − ∏ₜ(1 − pₜ)`를 쓴다. 슬레이트 1회당 M=200이면 오차 <2%.
→ 이것만 고쳐도 기존 로그는 못 살리지만 **앞으로의 측정은 정상화**된다.

### P0-b. 평점 신호 복구
- Places 보강(키 필요) 또는
- **대체 지표**: 우리가 가진 것 — 사진 수·메뉴 수·`quality` 평균·팀 방문 빈도.
  "팀이 사진을 많이 남긴 곳 = 인상 깊었던 곳"은 약하지만 **0보다 훨씬 낫다**.

### P1. contextFit 대체
정규식 대신 **이미 있는 피처 벡터**(taste 5축 + price)를 맥락과 내적한다.
예: 비/추위 → `light` 낮고 `oily/salty` 높은 쪽 가산. 혼밥 → `price` 낮고 `light` 높은 쪽.
→ 카테고리 21곳 사각지대가 사라지고 점수가 **연속 분포**가 된다.

# 5. 종합 반론 (이 감사에 대한 반론)

- **"프로토타입인데 과한 지적 아닌가?"** — 치명 1·2는 *지금 사용자가 겪는* 문제다
  (추천이 사실상 랜덤). 치명 3은 *개선을 측정할 수단*이 고장 난 것이라, 방치하면
  이후 모든 엔진 작업이 근거 없는 추측이 된다.
- **"취향 모델이 좋으면 되지 않나?"** — 취향은 `MIN_TASTE=5` 이후에만 켜지고, 그전엔
  치명 1·2 때문에 랜덤이다. 즉 **신규 유저 경험 전체가 엔진 밖에 있다.**
- **"평점이 없으면 그냥 가중치를 재분배하면?"** — 가능하지만 그러면 남는 건 contextFit뿐이고,
  그게 고유값 2개짜리라 문제가 그대로다. **P1(피처 기반 맥락)이 선행되어야** 재분배가 의미 있다.

## 부록 — P0 조치 결과 (2026-07-26 완료)

### P0-a. propensity → 마진 포함확률
`buildSlate`가 로깅하던 `p_i`(첫 draw 확률)를 **몬테카를로로 추정한 π_i**(K개 슬레이트 포함확률)로 교체.
해석적 근사 `1−(1−p)^K`는 비복원 효과를 무시해 오차가 커서 채택하지 않음(실측 확인).

| 지표 | 수정 전 | 수정 후 |
|---|---|---|
| 실제/로깅 배율 평균 | **7.07x** | **1.08x** |
| 배율 범위(비균일 = 편향) | 5.9 ~ 14.5x | 0.61 ~ 3.10x |

→ off-policy(IPS)·A/B 계기 정상화. 회귀 테스트 `scorer.propensity.test.ts` 5건 추가.

### P0-b. 평판 사전확률 (rating=0 대체)
가짜 평점을 데이터에 넣지 않고, **엔진 안 폴백**(`reputationPrior`)으로 처리 — API의 `rating=0`은
"평점 없음"이라는 정직한 값으로 유지된다. 사전확률은 인제스천 증거로 계산:
`0.55·log(사진 수) + 0.25·컷 다양성 + 0.20·메뉴 확보` → [0.25, 0.85] 압축
(0점이면 탐색에서 완전 배제되므로 하한을 둔다).

| 지표 | 수정 전 | 수정 후 |
|---|---|---|
| 점수 고유값 | **2 / 118** | **45 / 118** |
| 점수 범위 폭 | 0.060 | **0.414** (7배) |
| 커버리지(100세션) | 116/118 | 115/118 (유지) |

→ 콜드 유저에게도 순위가 생김. 외부 평점이 들어오면 `rating` 기반 계산이 자동 우선.

### 알려진 한계 (정직한 기록)
- **규모**: 포함확률 추정은 O(M·K·n). 현재 카탈로그 n=118에서 **1.09ms**로 무해하나,
  n=2115(구 OSM 규모)면 **~90ms**로 요청 경로에 부담. 연산 예산 상한을 뒀지만 추정 품질을 위해
  최소 60회는 돌린다. 카탈로그가 수천 규모로 커지면 **Fenwick 트리로 draw를 O(log n)** 화해야 한다.
- 과거에 쌓인 rec_events의 propensity는 여전히 틀린 값이다. **소급 보정 불가** —
  off-policy 분석은 이 수정 이후 데이터로만 해야 한다.
- P1(contextFit 피처 기반 교체)은 미착수. 지금 점수 다양성은 대부분 사전확률에서 나온다.

## 부록 2 — P1 조치 결과 (2026-07-26 완료)

### P1-a. contextFit: 카테고리 정규식 → **피처 벡터 내적**
맥락(날씨·시간·동행·인텐트)을 "원하는 피처 방향" 가중 벡터로 표현하고,
사진·메뉴에서 뽑은 연속 피처와 내적한다: `cf = clamp(0.5 + Σ wⱼ·(xⱼ − 0.5))`.

정규식을 버린 이유(3가지 모두 실제로 겪은 문제):
1. 매칭 안 되는 카테고리가 통째로 사각지대 — `레스토랑`·`바` 등 **21곳이 항상 0.5 고정**
2. 언어가 바뀌면 전부 무력화 — `features.ts`에서 한글 정규식 탓에 전 카탈로그가 NEUTRAL로 떨어진 전례
3. 값이 이산점 몇 개뿐이라 순위를 못 매김

### P1-b. 절편(bias) 항 추가 — FEATURE_DIM 8 → 9
상수 1 성분을 넣어 모델이 **기저 선호율**을 학습할 수 있게 했다.
없으면 "이 유저는 전반적으로 잘 좋아한다"를 8개 맛/가격 축에 억지로 실어야 했다.
`contextFit` 계산에서는 절편을 제외한다(맥락 판단 대상이 아니므로).

### 누적 효과 (감사 시점 → P0 → P1)

| 지표 | 감사 시점 | P0 후 | **P1 후** |
|---|---|---|---|
| 점수 고유값 | 2 / 118 | 45 / 118 | **106 / 118** |
| 점수 범위 폭 | 0.060 | 0.414 | **0.482** |
| propensity 배율 평균 | 7.07x | 1.08x | **1.07x** |
| propensity 최대 배율 | 14.5x | 3.10x | **4.47x** → Jeffreys 평활 적용 후 안정 |
| 커버리지(100세션) | 116/118 | 115/118 | **115/118** (유지) |
| 슬레이트 1회 지연 | ~0.6ms | 1.09ms | **1.69ms** |

**추가 개선**: 희소 항목의 몬테카를로 추정이 0이 되어 IPS가 폭발하던 문제를
단순 바닥값 대신 **Jeffreys 평활 `(h+0.5)/(M+1)`** 로 교체 — 최대 배율 10.4x → 4.47x.

회귀 테스트 10건(`scorer.propensity.test.ts`), 전체 349건 통과.
