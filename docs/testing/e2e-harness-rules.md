# E2E Harness Rules

이 문서는 화면 스모크가 아닌 **운영 불변식**을 검증하는 Playwright 하네스의 기준이다.

## 필수 규칙

1. 인증 경계: 익명 사용자는 개인 프로필·작성 화면을 볼 수 없고, 보호된 동작은 곧바로 Google OAuth로 간다.
2. 소유권: 수정·삭제·댓글·좋아요·신고는 서버 세션의 `sub`를 기준으로 검사한다. UI의 작성자 ID는 권한 근거가 아니다.
3. 멱등성: 결과 확정·게시·반응의 재시도는 동일 `idempotency_key`로 한 번만 기록한다. 네트워크 재전송, React 재렌더, 새로고침이 중복 행을 만들면 실패다.
4. 상태 격리: 로그아웃은 세션 쿠키, 게스트 ID, 현재 방, 개인 캐시를 모두 끊는다. 다음 사용자가 이전 여정을 볼 수 없다.
5. 추천 다양성: 동일 조건의 연속 요청은 후보 풀·하드 제약을 유지하면서, 최근 노출 감쇠와 탐색으로 동일 순서에 고정되지 않는다.
6. 서버 원본성: 포스트·댓글·좋아요·런치 결과는 새로고침 후에도 서버에서 재구성된다. localStorage만으로 성공 상태를 만들 수 없다.

## 실행 계층

- `npm run test:e2e`: Playwright 브라우저 경계 테스트. API는 필요한 경우 라우트 모킹으로 인증 상태와 리다이렉트를 결정론적으로 재현한다.
- D1 통합 하네스(배포 환경): 각 쓰기 요청에 고유한 테스트 네임스페이스를 부여하고, 실행 전후 행 수·소유자·중복 여부를 확인한다. 운영 데이터는 공용 키로 테스트하지 않는다.
- `npm run check` 및 `npm test`: 타입·순수 알고리즘 회귀 검증. E2E를 대체하지 않는다.

## 멱등성 계약

`POST /api/journey-winner`는 `idempotencyKey`가 필수다. 같은 키로 두 번 호출하면 첫 호출은 기록하고, 다음 호출은 `{ ok: true, duplicate: true }`로 응답하며 `rec_events` 행 수는 증가하지 않는다.
