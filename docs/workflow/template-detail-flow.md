# Template detail flow

## 목적

`/feed?tab=template`에서 템플릿을 고르는 행동과 코스 상세를 보는 행동을 분리한다. 템플릿 결과물을 먼저 충분히 본 뒤, 명시적인 `상세 코스 보기` CTA로 관련 코스에 진입한다.

## 라우팅 계약

- 목록: `/feed?tab=template`
- 기본 디자인 갤러리: `/templates`
- 템플릿 상세: `/template/:templateId?course=:courseId`
- 관련 코스: `/course/:courseId?from=template-detail&template=:templateId`
- 코스별 피드 모음: `/course/:courseId/feeds` + 현재 코스 상세의 query string
- 코스 상세의 뒤로 가기는 원래 템플릿 상세 URL을 복원한다.

프로필에서 진입할 때는 템플릿 상세 URL에 `from=profile`을 추가한다. 이어서 코스 상세로 이동할 때 `templateFrom=profile`을 전달해 `코스 → 템플릿 상세 → 프로필` 복귀 경로를 보존한다.

템플릿 ID는 `client/src/constants/coursemapTemplates.ts`의 `COURSEMAP_TEMPLATES`가 소유하고, 코스 ID는 `AppContext`가 소유한다. 템플릿 상세 URL에는 둘 다 필요하다.

## 화면 책임

- `TemplateCoursemapCard`: 템플릿 탭과 프로필에서는 템플릿 상세로 이동한다. 저장 목록 등 다른 사용처는 기존 코스 상세 이동을 유지한다.
- `TemplatesBrowsePage`: 코스 생성과 무관하게 에디터와 동일한 19개 ZIP 템플릿 디자인을 둘러보는 독립 갤러리다.
- `SHARE_TEMPLATES`: 코스 생성 후 공유 에디터와 독립 갤러리에서 함께 사용하는 단일 디자인 목록이다.
- `CourseFeedsPage`: `FeedPost.courseId`가 선택한 코스 ID와 같은 실제 피드를 최신순 또는 좋아요순으로 모아 보여주며, 결과가 없으면 피드 작성 CTA가 있는 빈 상태를 표시한다.
- `CourseShareTemplatePreview`: 공유 에디터의 기본 사진 배치를 읽기 전용 카드로 렌더링한다.
- `TemplateInfoSheet`: 사진이 들어가기 전 기본 양식, 슬롯 수, 비율, 추천 코스 정보를 표시하는 공용 바텀시트다.
- `TemplateArtwork`: 목록 카드와 상세 히어로가 동일한 결과물을 렌더링하도록 공유한다.
- `TemplateDetailPage`: 큰 템플릿 히어로, 관련 코스 요약, 템플릿에 사용된 식당 목록, 단일 코스 CTA를 제공한다.
- `TemplateDetailPage` 식당 카드는 첫 탭으로 선택하고, 왼쪽 스와이프 또는 화살표로 `RestaurantDetailSheet`를 연다.
- `CourseDetailPage`: `from=template-detail`일 때 템플릿 상세로 복귀한다.
- `CourseDetailPage`: 코스맵 우측 상단의 `코스맵 공유`는 Web Share API로 제목·설명·정규 코스 URL을 시스템 공유 시트에 전달하고, 미지원 환경에서는 링크를 복사한다.
- 코스맵의 공유·템플릿·저장 액션은 지도 내부 오버레이가 아니라 지도 바로 위의 액션 행에 둬 지도 내용을 가리지 않는다.
- 프로필에서 연 `TemplateDetailPage`는 수정·삭제 액션을 제공한다. 삭제는 프로필 템플릿만 숨기고 원본 코스와 연결 피드는 유지하며, 수정은 실제 코스 편집기로 이동한다.
- `templateFrom=profile`로 이어진 코스 상세는 소유 코스로 취급해 `복사해서 편집` 대신 `편집`을 표시한다.

## 구현·검증 루프

후속 작업자나 서브 에이전트는 아래 순서로 회귀를 확인한다.

1. `pnpm check`로 라우트 파라미터와 데이터 타입을 확인한다.
2. `pnpm test`로 기존 도메인 로직 회귀를 확인한다.
3. `pnpm build`로 실제 번들 생성을 확인한다.
4. 모바일 뷰포트에서 `/feed?tab=template`을 열고 첫 카드를 누른다.
5. 템플릿 상세에서 큰 결과물, 식당 수/순서, `상세 코스 보기`를 확인한다.
6. 상단 템플릿 이름을 눌러 사진이 없는 기본 양식 정보가 열리는지 확인한다.
7. `/templates`에서 공유 에디터와 동일한 19개 기본 디자인과 각 정보 바텀시트를 확인한다.
8. 프로필의 템플릿 카드에서 상세로 이동하고 뒤로 가면 프로필로 복귀하는지 확인한다.
9. CTA로 코스 상세에 진입한 뒤 뒤로 가기를 눌러 동일 템플릿 상세로 복귀하는지 확인한다.
10. 템플릿 상세의 식당을 탭한 뒤 왼쪽으로 밀어 상세·후기 시트가 열리는지 확인한다.
11. 코스 상세의 `이 코스로 만든 피드`에서 `FeedPost.courseId`가 같은 피드만 표시되는지 확인한다.
12. 피드를 새로 작성하거나 연결 코스를 수정한 뒤 양쪽 코스의 피드 개수가 즉시 갱신되는지 확인한다.
13. 코스별 피드에서 최신순과 좋아요순을 전환하고 동점은 최신 피드가 먼저 오는지 확인한다.
14. 코스별 피드와 메인 피드 모두에서 다중 사진을 좌우로 넘겼을 때 카운터와 점 표시가 갱신되는지 확인한다.
15. 잘못된 template/course ID에서 진입 출처에 맞는 복귀 UI가 표시되는지 확인한다.
16. 템플릿 상세에서 진입한 코스맵의 `코스맵 공유` 버튼이 시스템 공유 시트를 열고, 취소해도 화면에 오류가 남지 않는지 확인한다.
17. 프로필 템플릿 상세에서 수정·삭제 버튼이 보이고, 삭제 후 프로필 목록에서만 사라지는지 확인한다.
18. 프로필 템플릿에서 이어진 코스 상세에 `편집`이 표시되고, 수정 저장 후 프로필에 변경 내용이 유지되는지 확인한다.

## 변경 시 지켜야 할 불변 조건

- 템플릿 탭과 프로필의 템플릿 카드 클릭은 코스 상세를 직접 열지 않는다.
- 코스로 이동하는 주 CTA 문구는 `상세 코스 보기`로 유지한다.
- 템플릿 카드와 상세 히어로의 사진 슬롯·라벨 결과는 같아야 한다.
- 기본 디자인 미리보기에는 코스 사진을 합성하지 않고 코스맵 원본 `template.image` 또는 공유 원본 `template.background`를 사용한다.
- `/templates`와 공유 에디터의 전체 목록은 반드시 `SHARE_TEMPLATES` 한 곳에서 관리한다.
- 코스별 피드 모음은 별도 복제 데이터를 만들지 않고 `feedPosts.filter(post => post.courseId === courseId)`를 단일 기준으로 사용한다.
- 코스별 피드 모음은 진입한 코스 상세의 query string을 보존해 동일한 이전 화면으로 복귀한다.
- 템플릿 상세에서는 하단 탭바를 숨겨 CTA와 충돌하지 않게 한다.
